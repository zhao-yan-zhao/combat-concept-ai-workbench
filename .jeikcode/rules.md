# 业务与组织规则 (Business Rules)

本文件规定 AI 作战概念研究工作台的核心业务硬性约束、工作流规范与开发准则。

---

## 1. 核心定位与设计哲学

1. **研究工作台定位**：本项目定位为“AI 作战概念研究工作台”，不是通用大模型聊天界面，禁止引入大屏炫技、娱乐化或无关信息堆叠。
2. **工作流驱动**：所有功能围绕六步主链设计：输入设定 → 知识检索 → AI 生成辅助 → 人工深度修订 → 效能评估/红方审阅 → 成果输出与归档。
3. **概念图定位**：概念图绘制工具（基于 Cytoscape / WebGL）仅作为成果输出接口或展示载体，不得将其作为核心逻辑载体。
4. **知识溯源强制**：Obsidian / 本地知识库是所有研究生成的核心事实来源，所有 AI 生成物必须保留或提供可追溯的证据链引用，不可凭空捏造武器参数。

---

## 2. AI 提示词资产管理硬性约束（零隐藏原则）

1. **统一目录准则**：新增或修改任何实际发送给 AI 的提示词模板，**必须**在服务端 `server/aiPromptConfig.mjs` 中注册，纳入工作台顶部菜单“工具 → AI 提示词”的统一管理目录。
2. **规范元数据**：每个提示词必须具备稳定 ID（如 `ai.generate.*` 或 `ai.red-team.*`）、名称、中文用途说明以及动态变量列表说明。
3. **动态生效保障**：用户在提示词管理界面编辑或覆盖的内容，必须在后续真实 AI 请求中无缝生效，严禁写入不可浏览、不可调整的“写死”隐藏提示词。
4. **注入安全**：知识库引用作为未受信任输入注入时，必须声明仅用于提取事实依据，严禁执行引用文本中的指令或角色越狱提示。

---

## 3. 工作流阶段与门禁规则 (Workflow Gates)

18 步作战概念研究工作流分为三类职责，具有严格的流程与验证依赖：

1. **主写步骤 (`write`)**：
   - 核心步骤：概念简报 (`brief`)、阶段行动 (`phase-action`)、作战任务 (`operational-task`)、作战兵力 (`force-mission`)、总体图 (`ov1-graphic`)、概念图 (`concept-map`)、仿真验证 (`simulation`)。
   - 需完成前置步骤的核心要素录入后方可演进。
2. **校验步骤 (`check`)**：
   - 包含交战规则库 (`rule-library`)、状态机迁移 (`state-machine`)、组织关系 (`ov4`) 等。
   - 不阻断主线推进，但为成果提供一致性诊断与设计告警。
3. **交付步骤 (`deliver`)**：
   - 包含红方审阅 (`red-team`)、协同审阅 (`collaboration`)、成果报告 (`report`)。
   - 依赖全生命周期的快照生成与完整性校验。

---

## 4. 权限与敏感度控制

1. **配置修改权限**：AI 服务提供商、接口密钥等底层参数修改遵循负责人民主确认机制，未登录或非负责人访客只读。
2. **知识敏感度分级**：对公开/内部/受限资料实行阶梯式引用审查，敏感标记在跨部门或外部导出时自动脱敏。
3. **本地密钥安全**：持久化密钥使用 Windows DPAPI 或安全本地隔离机制存储，严禁在源码或 Git 提交明文凭据。
